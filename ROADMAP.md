# Roadmap toward a usable stable standard

This describes intended work, not implementation, adoption, or certification claims.

| Stage | Deliverable | Evidence needed to advance |
|---|---|---|
| Draft foundation | Standard, assessment procedure, schemas, examples, adoption guide, checker, explorer and contribution process | Repository verification; explicit publication and licensing decisions |
| Adoption feedback | Actual bounded reviews in different domains | Exact version/scope, concrete ambiguity or overhead, disposition and counterexamples |
| Draft revision | Resolved contradictions, realistic evidence expectations, documented schema/policy boundaries and migration notes | Traceable proposals, review rationale, positive and negative examples, tooling checks |
| Stable proposal | Coherent 1.0.0 candidate | Substantive review of every requirement; adoption usefulness; resolved material issues; documented governance |

Immediate priorities are resolving rights/licensing/maintainership, exercising actual claim and operational reviews, documenting ambiguity and disproportionate overhead, and evaluating which narrative obligations warrant support in a later schema version. Domain review should cover security, AI evaluation, physical systems, commercial claims and measurement where practical.

A proposed requirement should name the failure it prevents and evidence an adopter can realistically provide. A relaxation should identify lost assurance and alternatives. [Governance](GOVERNANCE.md) defines compatibility and stable-ID rules.

The project does not currently provide a certification authority, hosted evidence vault, production authorization engine, or automatic truth evaluator. Those proposals would need their own scope, evidence, governance and authority.
