## Review findings and dispositions

- The initial GitHub destination was empty. The foundation imports only the separate generic candidate files, without the preparation workspace's Git history or private engagement material.
- Adoption required a smaller entry point. The new guide, applicability table, synthetic walkthrough and unknown-first CSV matrix support one bounded review without replacing the full assessment procedure.
- The direct checker is not a general JSON Schema evaluator. A separate optional engine now evaluates the actual schema documents with explicit format checks; a negative test demonstrates that schema acceptance does not establish evidence relationships or declared policy.
- Requirement navigation could drift from the standard. The catalog and explorer now derive from source bytes, and repository checks reject stale output. Mixed keywords remain visible without assigning an invented requirement level to the entire paragraph.
- URL fragment decoding could stop explorer initialization on malformed input. The explorer now accepts known raw requirement identifiers and safely ignores other fragments; a simulated DOM check covers malformed and unknown fragments.
- Assessment generation must not replace an existing review. Exclusive file creation and a regression test preserve existing files; every generated result begins UNKNOWN with applicability UNREVIEWED.
- Older preparation records retain their original dates and scope. [PREPARATION_VERIFICATION.md](PREPARATION_VERIFICATION.md) and [LOCAL_VALIDATION.json](LOCAL_VALIDATION.json) describe October preparation, not current repository or remote acceptance.

This is an implementation self-review and local tool verification. It is not independent review of the 118 normative requirements or external accreditation.
